## 1    Introduction

<a id="P009"></a>

S4-261722 [1] was agreed as the skeleton for the Permanent Document ULBC-9 on RTP header reduction and system integration, capturing the background on the transport architecture for RTP header reduction. In addition:

<a id="P010"></a>

vivo's S4-261714 [4] introduced the SA2 progress, the scope of the RTP header reduction work, and the RTP header field analysis;

<a id="P011"></a>

Qualcomm further introduced S4-261715 [2] on DTMF with non-IP delivery over NB-IoT NTN, proposing to convey a DTMF event as a telephone event by a header-reduced RTP packet per RFC 4733/TS 26.114 Annex G and S4-261717 [3] on assumptions for RTP header reduction and MTSI integration;

<a id="P012"></a>

Draft WID S4-261098 [5] on MTSI integration for IMS Voice over GEO also discussed such the scope and objectives of such work.

<a id="P013"></a>

This contribution is based on the discussion above and updates ULBC-9 [1] accordingly.

Introduction

<a id="P020"></a>

At the TSG SA#112 plenary meeting, the ULBC-MED WID in SP-260696 was approved [1], which includes the following objective related to the RTP header:

<a id="P021"></a>

Specification of an RTP payload format for the ULBC codec and determination of essential fields for RTP header reduction.

<a id="P022"></a>

The present document is the Permanent Document ULBC-9 of the ULBC-MED work item. It captures the scope, working assumptions, solutions and consolidations on RTP header reduction and the related system integration aspects for IMS voice over NB-IoT(GEO). The consolidations captured in the present document will be reflected in the ULBC RTP payload format specification.

<a id="P023"></a>

Transport of GEO voice and applicability of RTP header reduction

<a id="P024"></a>

Scope

<a id="P025"></a>

<a id="P026"></a>

<a id="P027"></a>

<a id="P028"></a>

RTP header field analysis

<a id="P034"></a>

RTP is defined in IETF RFC 3550 [4]. In a typical two-way voice call, the first 12 bytes of the RTP header are mandatory; the CSRC list and header extension are optional and not used in a point-to-point voice session. Each field serves a different function for audio transport, and different features rely on different fields, as summarised in Table 1 based on TS 26.114 [5] and related RTP payload specifications.

Annex-A: Background of RTP header reduction

<a id="P074"></a>

As specified in Clause 4.13 of TS 23.401 [2], IMS voice over NB-IoT (GEO) supports two mechanisms:

<a id="P075"></a>

## 1. IP-based (mandatory):

<a id="P076"></a>

IMS signalling and voice are transported as IP packets, with RoHC recommended for header compression. The protocol stack over the radio is ROHC (RTP/UDP/IP) / PDCP / RLC / MAC. In the RoHC steady state (Profile 1, RTP/UDP/IP), the 40-byte RTP/UDP/IP headers can be compressed to 1–3 bytes [8], resulting in an overall protocol overhead of about 8 bytes (3 + 1 + 1 + 3).

<a id="P078"></a>

Figure 1: Protocol stack from UE to IMS-AGW: IP-based transport with ROHC (no UHRR)

<a id="P079"></a>

## 2. UHRR-enabled (optional):

<a id="P080"></a>

UHRR optionally removes and restores the UDP/IP headers at the UE/PDN GW. The RTP header can also be reduced and restored at the UE/AGW. In this case, the protocol stack is RTP / PDCP / RLC / MAC. The 12-byte RTP header is transmitted with further reduction or compression.

<a id="P083"></a>

Figure 2: Protocol stack from UE to IMS-AGW: UHRR enabled with reduced RTP header
